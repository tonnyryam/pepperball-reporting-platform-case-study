# System capability matrix

| Platform surface | Purpose | Publicly supportable status | Public boundary |
| --- | --- | --- | --- |
| Cloud-document discovery | Find current and late operational evidence | Deployed and observed | No tenant, folder, or source names |
| Version-aware intake | Retain originals and distinguish live from historical work | Deployed and tested | No private identifiers or paths |
| Raw/normalized/governed facts | Preserve evidence, normalize fields, expose current business material | Integrated and regression-tested | No schema or proprietary definitions |
| Field-scoped validation | Keep missing distinct from proved zero | Deployed and certified in report outputs | No employee or operational facts |
| Expected-output accounting | Detect absent, pending, published, read-back, protected, and terminal obligations | Deployed through existing observers/checkpoints | No database coordinates |
| Four report families | Produce shift draft, daily, weekly, and weekly downtime products | Naturally verified as a shared reliability domain | No templates or exact schedules |
| Deterministic workbooks | Store client-independent values in two visible sheets | Deployed and raw-package certified | Synthetic workbook only |
| Governed material identity | Separate business changes from capture-only metadata | Deployed and naturally verified | Generalized semantics only |
| Conditional publication | Advance the canonical item with conflict protection | Deployed and exact-readback certified | No item IDs, URLs, or ACLs |
| Accepted-write settlement | Resolve lost responses through GET without a second PUT | Deployed and naturally observed | Synthetic state model only |
| Repair and backfill | Fairly converge eligible technical gaps | Deployed with bounded, durable state | No protected-item details |
| Terminal/protected holds | Prevent repair from rewriting security- or ownership-held evidence | Deployed and regression-tested | Hold identities omitted |
| Report health doctor | Explain output status without write authority | Deployed as a read-only surface | No production screenshots |
| Governed API and portal | Provide report and diagnostic access | Integrated read/interaction plane | Routes and topology omitted |
| Assistant-facing summaries | Present client-independent status and evidence | Integrated with governed data boundaries | No prompts, accounts, or private content |
| Document-knowledge gates | Control future knowledge features by access, privacy, and retention | Prepared/gated; not claimed generally active | Architecture details omitted |
| Privacy-safe interaction telemetry | Measure citation interaction without exporting private content | Implemented and tested; deployment status stated separately | Event schema omitted |
| Immutable release pipeline | Validate, serialize, activate, observe, and restore workers | Deployed and repeatedly exercised | No cloud resource identities |
| One-writer lease | Prevent overlapping publishers | Deployed and observed | Lease implementation omitted |
| Exact rollback | Restore the certified predecessor on material regression | Exercised through failed-restored releases | Version identifiers omitted |
| Evidence and handoff | Bind claims to tests, readback, runbooks, and owner acceptance | Complete technical package; owner transfer/archive remains separate | Private evidence stays private |

Status language is intentionally precise. `Prepared`, `implemented and tested`,
`deployed`, and `naturally verified` are different evidence grades.
